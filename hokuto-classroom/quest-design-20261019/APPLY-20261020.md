# 호쿠토증권 구현 인수 지침 — v9-final1020b

모든 자료는 가상입니다. 운영 반영의 증거가 아님. 아스트라는 실제 브라우저와 운영 자료를 검사하지 못했습니다. 아래 절차는 헤르메스가 구현 가지에서 실행하고 증거를 남길 인수 조건입니다.

## 1. 범위와 일정

화면·문구·표시 필터만 수정합니다. 선정 엔진, 선정 규칙, 서버 쓰기, DB 칸, 번역 엔진, 매수 금액·비중·주식 수는 건드리지 않습니다. 제목 버튼도 화면 표시만 바꿉니다. 추가 후보 로봇 시험은 11/1까지 계속하며 디자인의 선행 조건이 아닙니다.

- 10/21: 시안·지침 확인.
- 10/22: Claude 웹 검토와 수정 후 헤르메스 구현 시작.
- 10/23: 같은 입력 비교, 360px 검사, 아스트라·코덱스 증거 검토.
- 10/24 토요일: 운영 반영 후보일.
- 10/25 일요일: 반영 후 확인·수정.

범준 승인 전에는 운영 반영하지 않습니다. 날짜가 됐다는 이유로 반영하지 않습니다. 화면 구현 검사는 운영 DB 쓰기 없이 읽기 자료로 수행합니다. 최종 승인된 화면 파일 교체만 시그마가 수행합니다.

## 2. 테마와 출처

집중 3개 = 6개월 추세가 플러스인 테마 중, 최근 20거래일 수익이 큰 상위 3개 테마

★ 6개는 테마별 종목들의 최근 20거래일 수익 평균 상위 6개 테마입니다. 운영이 계산한 테마와 후보를 그대로 읽으며 화면에서 재선정하지 않습니다. 돈몰림과 전환 표시를 유지합니다.

집중 테마 후보는 실제 A·B·C 출처를 우선 표시하고, 그 밖은 실제 D 출처를 표시합니다. 집중 테마의 D-only 기록을 A·B·C로 바꾸지 않습니다. 기록이 맞지 않으면 확인 필요입니다. 중복은 같은 선정 회차·종목 기준으로 한 번 세며, 레인별 소속 원본은 보존합니다. 서로 다른 선정 시각의 회차는 합치지 않습니다. 시각이 없는 같은 날짜·같은 종목은 일별 표시에서 중복 제거하며 세부 회차는 확인 필요입니다. 종목 수를 3개로 제한하지 않습니다.

‘집중 테마가 아님’은 ★ 테마에 대한 중립 안내입니다. 나쁨·제외 판정 색을 쓰지 않습니다.

## 3. 전환일 처리

화면 필터 이름은 ‘옛 규칙 / 전환일 / 집중 규칙’입니다.

1. 선정일 ~10/19는 옛 규칙입니다.
2. 10/20은 선정 시각이 있으면 확인된 전환 경계 전후로 나눕니다. 시각이 없으면 전환일에만 표시합니다. 경계 자체가 미확인이어도 전환일에 남깁니다.
3. 10/21 이후는 집중 규칙입니다.

전달받은 잠정 경계는 10/20 17:45이며, 낮 약 10:23~17:44 선정분은 옛 규칙이라는 설명입니다. 헤르메스가 실제 선정 기록·작업46 적용 기록·시간대를 대조해 확정해야 합니다. 잠정값은 display-policy.js의 transition 한 곳에만 있고 confirmed=false입니다. 확인 후 같은 설정의 경계와 확인 상태를 갱신합니다. 화면에는 경계 시각을 박아 넣지 않습니다. 일본시간 기준으로 비교하며 시간대 없는 값의 해석도 확인합니다.

세 구간의 ABC 배정 수·LANE_NONE을 합산하지 않습니다. DB 규칙 버전 칸은 만들지 않습니다. 현재 시안의 시각 없는 10/20 예시 3건은 전환일이며 홈 집중 규칙 성적표에서 제외합니다.

## 4. 성과 입력과 빈 칸

실제 화면은 성과 DB의 최신 읽기 결과를 받습니다. 시안·과거 화면의 숫자를 복사하지 않습니다. 10/20 14:31 분할 혼입 교정 후 자료인지 확인합니다. 아래는 필요한 칸의 목록이며 새 DB 설계가 아닙니다.

| 필요한 값 | 현재 확인 수준 | 값이 없을 때 |
|---|---|---|
| 선정일 | 사용자 설명상 존재, 실제 DB 미열람 | 없음으로 기록, 구간 추정 금지 |
| 선정 시각 | 없음: 운영 열·값 미제공 | 10/20은 전환일 |
| 레인 | 없음: 운영 열·값 미제공 | 출처 확인 필요 |
| 테마 | 없음: 운영 열·값 미제공 | 집중 여부 확인 필요 |
| 종목 | 없음: 운영 열·값 미제공 | 연결 확인 필요 |
| 집중 여부 | 별도 DB 칸 요구 없음 | 당시 테마와 당시 집중 테마를 읽어 비교; 자료 없으면 확인 필요 |
| 1·5·20·60거래일 수익 | 사용자 설명상 기존 기록 있음, 실제 값 미열람 | 빈 이유 확인 |
| 40거래일 수익 | 현재 없음, 10/21 추가 예정 | 기록 시작 기준 적용 |

여기서 ‘없음: 미제공’은 아스트라에게 운영 자료가 없다는 뜻이며 DB에 열이 없다고 단정한 것이 아닙니다. 헤르메스는 실제 열 이름과 존재 여부를 읽기 확인해 같은 표에 적고, 실제로 없는 칸은 ‘없음’으로 적습니다. 새 칸을 만들지 않습니다.

1·2·3개월은 20·40·60거래일이며 1·5일은 접습니다. 표시 순서는 다음과 같습니다.

1. 40일 칸이고 선정일이 10/21 전이면 ‘이 기간은 기록 시작 전’.
2. 해당 기간의 DB 결과가 있으면 그대로 표시. 0%도 실제 결과입니다.
3. 아직 기간 전이면 ‘결과 기다리는 중 (남은 거래일 N일)’.
4. 기간이 지났고 필요한 가격 누락을 확인했으면 ‘가격을 못 구함’.

N은 기존 거래일 달력·평가 시작 기준으로 구합니다. 주말만 빼거나 달력 일수로 계산하지 않습니다. 기간과 가격 누락의 근거가 없으면 ‘확인 필요’로 표시하며 새 DB 상태 칸을 요구하지 않습니다. 기간별 결과가 있는 건수는 ‘표본 N건’으로 작게 표시합니다.

40일 첫 결과 11/9 무렵과 집중 규칙 20일 첫 결과 11월 중순은 전달받은 추정입니다. 전자는 ‘10/21 이후 선정분부터 40거래일’ 조건과 양립하지 않습니다. 두 조건 중 무엇을 고칠지 확인 전에는 시안처럼 확인 필요를 함께 표시하고, 확정 예상일로 안내하지 않습니다. 날짜 안내의 실행 원본은 ui-copy.js의 first40Estimate·first20FocusEstimate·estimateConflict입니다.

## A. 일컴 Chrome 360px 검사

헤르메스가 일컴 Chrome에서 구현 가지의 새 화면을 엽니다. 개발자 도구의 기기 도구모음을 Responsive로 설정하고 360×800, 페이지 확대 100%로 고정합니다. 기본 글자와 기본 글자의 130% 두 번 검사합니다.

큰 글자는 해당 화면의 문서에서 현재 html의 계산된 font-size를 확인한 뒤 그 값의 1.3배를 임시 적용합니다. 검사 전후 값을 기록하고 새로고침으로 원복합니다. 고정 px 문구가 그대로 남는지도 별도 기록해 큰 글자 검사가 실제 적용됐는지 확인합니다. iframe 미리보기라면 바깥 도구모음이 아니라 화면 문서를 대상으로 적용합니다.

|---|---|---|
| 홈 | home.html#view=home | home.png |
| 작전실02 | #view=room&room=ops | ops02.png |
| 전략실03 | #view=room&room=strategy | strategy03.png |

저장 위치는 구현 가지의 `design-review/v9-final1020b/screens/360x800/default/`와 `design-review/v9-final1020b/screens/360x800/font130/`입니다. 표의 파일 이름을 각각 저장하고, 결과는 `design-review/v9-final1020b/mobile-check.md`에 화면별로 기록합니다.

통과 기준은 모두 충족해야 합니다.

- 페이지와 내부 표의 가로 스크롤 0. documentElement의 scrollWidth가 clientWidth를 넘지 않고, 표 안에서도 좌우 이동이 필요 없어야 합니다.
- 글자 잘림 0. 제목·빈 칸·출처·표본 수·버튼·팝업을 끝까지 읽을 수 있어야 합니다.
- 실제 누르는 영역의 너비와 높이가 각각 44px 이상. getBoundingClientRect 값으로 확인합니다.
- 한국어·일본어 줄바꿈 이상 0. 회사명 원문 외 한자 금지 조건도 확인합니다.
- 두 제목 상태, 번역 대기·검사 탈락, 세 날짜 구간과 세 빈 칸 이유를 확인합니다.

현재 없는 상태는 별도의 가상 검사 입력으로 재현하고 운영 자료와 섞지 않습니다. 실제 일본어 원문 제목에 회사명 외 한자가 있을 때의 표시 방식은 범준 확인 전 임의로 바꾸지 않습니다. 실제 브라우저 증거가 없으면 통과로 적지 않습니다.

## B. 같은 입력 비교

작업46이 적용된 동일 운영 자료 한 벌을 읽기 전용으로 고정합니다. 기준 시각·원본 파일 목록·파일 해시·교정 후 자료 여부를 `design-review/v9-final1020b/inputs/manifest.json`에 기록합니다. 원자료에 비공개 내용이 있으면 공개 시안 저장소에 올리지 않고 내부 검사 폴더에만 둡니다.

같은 자료를 옛 화면과 새 화면에 각각 연결합니다. 실시간 재조회로 입력이 달라지지 않게 합니다. 비교표는 `design-review/v9-final1020b/same-input.csv`에 항목·옛 값·새 값·의도한 변경 번호·통과 여부를 적습니다.

필수 비교는 종목 수, 가격, 판정, ★ 테마 6개, 집중 테마 3개, 레인별 후보, 성과 숫자, 기사 수입니다. 종목·테마·기사 ID와 순서, 점수, 등락·판정 색도 함께 대조합니다. 값과 집합을 비교하며 화면 반올림으로 차이를 숨기지 않습니다.

허용하는 의도한 변경 목록은 다음뿐입니다.

1. 집중을 테마로 명시한 문구·중립 표식·출처 표시.
2. 날짜별 세 구간 분리와 시각 없는 10/20 선정분의 전환일 격리. 구간별 표시 수는 달라질 수 있으나 원본 기록은 보존.
3. 홈 성적표에서 확인된 집중 규칙의 ABC만 표시. D-only·미확인 전환일 제외, 같은 회차 중복 한 번 계산.
4. 20·40·60거래일을 기본 칸으로 표시, 1·5일 접기, 빈 이유·남은 거래일·기간별 표본 수 표시. DB 수익률 자체는 동일.
5. 성과 메뉴 두 개와 안쪽 상세, 하루 변화의 알림홈 통합, 제목 버튼·모바일 줄바꿈 등 승인된 화면 구성.
6. 가상 일본어 제목의 회사명 외 한자 없는 표기. 실제 운영 기사 원문 변경은 허용 차이가 아님.

각 차이를 위 번호와 구체적인 대상 ID로 설명합니다. 목록에 없거나 설명되지 않은 차이는 모두 실패입니다. 원본 전체도 비교해 표시에서 빠진 기록이 데이터에서 삭제되지 않았는지 확인합니다. 같은 규칙·같은 입력의 화면 비교이지, 옛 선정 엔진과 새 선정 엔진을 비교하는 작업이 아닙니다.

## C. 옛 화면 보존과 되돌리기

헤르메스는 구현 전 옛 화면 HTML·JS·CSS·이미지의 전체 묶음을 별도 읽기 전용 폴더로 보존합니다. 원래 경로 구조와 파일 해시를 남기고, 새 화면은 다른 폴더에서 만듭니다. 공통 파일을 덮어써 옛 화면까지 바꾸지 않습니다. 현재 시안의 이전 기준 커밋은 `54cd5f0e71797a2404f83f4ca092c0a508900b85`이며 운영 롤백 버전을 뜻하지 않습니다.

운영의 실제 경로·배포 방식을 확인한 시그마가 인수 전에 ‘옛 화면 전체 묶음으로 전환하는 단일 명령’을 `design-review/v9-final1020b/rollback.md`에 적고 시험합니다. 서버 구성을 모르므로 명령이나 경로를 임의로 만들지 않습니다. 문서에는 이전 묶음·새 묶음·진입점·캐시 갱신 방법을 적습니다.

되돌리기는 2단계입니다. ① 준비된 단일 명령으로 화면 진입점을 옛 묶음으로 한 번에 전환하고 해당 화면 캐시를 갱신합니다. ② 홈·작전실·성과 화면을 열어 옛 버전과 기존 데이터 연결을 확인합니다. DB 복원이나 선정 엔진 변경은 없습니다. 실제 단일 명령과 시험 결과가 준비되지 않으면 반영하지 않습니다.

## D. 반영 금지 조건

범준 승인 없음, 새 문구 Claude 재검토 미완료, 실제 브라우저 증거 없음, 같은 입력 비교 실패, 전환 경계 미확인 자료의 임의 합산, 성과 숫자 출처 불명, 예상일 모순의 확정 표현, 되돌리기 미준비 중 하나라도 있으면 운영 반영하지 않습니다. 10/24는 후보일이며 10/25 확인 일정을 위해 검사를 생략하지 않습니다.

## E. 현재 확인하지 못한 것

아스트라가 확인한 것은 가상 입력·코드 실행·비시각 화면 검사입니다. 실제 브라우저, 운영 DB 구조·자료, 정확한 전환 시각, 실제 거래일 달력과 가격 누락 근거, 교정 후 성과값, 실제 배포·되돌리기 명령, 범준 승인과 Claude 재검토는 확인하지 못했습니다. 선정 엔진·서버 쓰기·DB 칸·번역 엔진은 변경하지 않았습니다.
