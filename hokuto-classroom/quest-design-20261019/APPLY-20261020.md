# 호쿠토증권 구현 인수 지침 — v9-final1020c

모든 자료는 가상입니다. 운영 반영의 증거가 아님. 아스트라는 실제 브라우저와 운영 자료를 검사하지 못했습니다. 헤르메스는 아래 절차를 구현 가지와 운영 자료의 읽기 사본에서 수행하고 증거를 남깁니다.

## 1. 범위·일정·필수 의존 순서

화면·문구·표시 필터만 수정합니다. 선정 엔진, 선정 규칙, 서버 쓰기, DB 칸, 번역 엔진, 매수 금액·비중·주식 수는 건드리지 않습니다. 제목 버튼도 화면 표시만 바꿉니다. 추가 후보 로봇 시험은 11/1까지 계속하며 디자인의 선행 조건이 아닙니다.

순서는 다음과 같습니다.

1. 47 반영(40일 마크·캐논·분할 교정 코드)이 main에 들어간 것을 확인합니다.
2. 10/21 17:30 배치 뒤 40일 마크 485건 이상 생긴 것을 확인합니다.
3. 10/23 같은 입력 비교와 실제 화면 검사를 수행합니다.
4. 10/24 토요일은 운영 반영 후보일입니다.
5. 10/25 일요일 확인·수정을 수행합니다.

10/21 시안·지침 확인, 10/22 Claude 웹 검토·수정 후 헤르메스 구현 시작 일정은 유지합니다. ①~②가 끝나지 않으면 ④ 새 화면 반영을 하지 않습니다. 47의 구현·main 반영·배치 실행은 이번 시안 작업에서 수행한 일이 아니며 완료로 간주하지 않습니다.

범준 승인 전에는 운영 반영하지 않습니다. 날짜가 됐다는 이유로 반영하지 않습니다. 구현 검사는 운영 DB 쓰기 없이 읽기 사본으로 수행하고, 승인된 화면 묶음의 운영 교체는 시그마가 수행합니다.

## 2. 테마·출처·중복 단위

집중 3개 = 6개월 추세가 플러스인 테마 중, 최근 20거래일 수익이 큰 상위 3개 테마

★ 6개는 테마별 종목들의 최근 20거래일 수익 평균 상위 6개 테마입니다. 운영이 계산한 테마·후보를 읽으며 화면에서 재선정하지 않습니다. 돈몰림과 전환 표시, 중립 회색의 ‘집중 테마가 아님’을 유지합니다. 종목 수를 3개로 제한하지 않습니다.

집중 테마 후보는 실제 A·B·C 출처를 우선 표시하고 그 밖은 실제 D 출처를 표시합니다. 집중 테마의 D-only 기록을 A·B·C로 바꾸지 않습니다. 자료가 맞지 않으면 확인 필요입니다.

- 레인 배정 수: 이벤트(신호) 단위로 셉니다. 같은 신호가 A와 D에 속하면 A 배정 1건·D 배정 1건이며 전체 신호 수는 1건입니다. 다른 신호를 같은 종목이라는 이유로 합치지 않습니다.
- 종목 성적: 같은 종목·같은 진입일·같은 진입가일 때만 한 줄로 합칩니다. 세 날짜 구간을 넘어서 합치지 않습니다.
- 같은 날 진입가가 다르면 별도 줄을 유지하고 ‘같은 날 중복 N’을 표시합니다. N은 그 종목·진입일의 서로 다른 진입가 줄 수입니다.
- 진입일·진입가·진입 기준이 없거나 맞는지 모르면 임의로 합치지 않습니다. 가격을 반올림해 같은 값으로 만들지 않습니다.
- 합친 줄은 원본 신호 연결을 보존합니다. 같은 진입 기준인데 결과값이 다르면 임의 선택·평균하지 않고 확인 필요로 남깁니다.

가상 자료의 같은 날·같은 종목 중복이 레인 차이인지 회차 차이인지는 아직 알 수 없습니다. 운영 자료로 확인할 항목이며 일별 한 번 계산으로 가정하지 않습니다.

## 3. 전환일과 한자 규칙

필터 이름은 ‘옛 규칙 / 전환일 / 집중 규칙’입니다. 선정일 ~10/19는 옛 규칙, 10/21 이후는 집중 규칙입니다. 10/20은 선정 시각과 확인된 전환 경계가 있으면 전후로 구분하고, 둘 중 하나라도 확인하지 못하면 전환일에 남깁니다.

잠정 경계는 10/20 17:45입니다. display-policy.js의 transition 한 곳에 confirmed=false로 두며 실제 선정 기록·작업46 적용 기록·시간대를 확인한 뒤 갱신합니다. 화면에 경계 시각을 고정 문구로 넣지 않습니다. 시각 없는 10/20 가상 예시 3건은 전환일이고 홈 집중 규칙 성적표에서 제외합니다. 세 구간의 ABC 배정 수·LANE_NONE은 합산하지 않으며 DB 규칙 버전 칸도 만들지 않습니다.

한자 금지의 범위: 한국어 UI 문구(버튼·안내·문구표·번역 결과 문장)에만 적용. 일본어 기사 원문 제목, 일본어 회사명·종목명 원문은 예외이며 바꾸지 않는다. 12월 이후 일본어 화면은 별도 문구표라서 이 규칙을 적용하지 않는다.

## 4. 성과 입력과 마크 상태

실제 화면은 교정 후 성과 DB의 최신 읽기 결과를 받습니다. 시안·과거 화면 숫자를 복사하지 않습니다. 아래는 읽기에 필요한 값이며 새 DB 칸 설계가 아닙니다.

| 필요한 값 | 현재 확인 수준 | 없을 때 |
|---|---|---|
| 선정일 | 사용자 설명상 존재, 실제 DB 미열람 | 구간 추정 금지 |
| 선정 시각 | 없음: 운영 열·값 미제공 | 10/20은 전환일 |
| 기존 신호 식별정보·레인 | 없음: 운영 열·값 미제공 | 이벤트 집계·출처 확인 필요 |
| 테마·종목 | 없음: 운영 열·값 미제공 | 연결 확인 필요 |
| 집중 여부 | 별도 DB 칸 요구 없음 | 당시 테마·당시 집중 테마로 확인; 자료 없으면 확인 필요 |
| 진입일·진입가·진입 기준 | 없음: 운영 열·값 미제공 | 성적 중복을 임의로 합치지 않음 |
| 1·5·20·40·60거래일 마크 행·수익 | 기존 기록과 47 변경 설명만 받음, 실제 DB 미열람 | 행 없음과 조회 미확인을 구분 |

‘없음: 미제공’은 아스트라에게 운영 자료가 없다는 뜻이며 DB 열이 없다고 단정한 것이 아닙니다. 헤르메스가 실제 열 이름·존재 여부를 읽기 확인해 표에 적고, 실제 없는 값은 ‘없음’으로 적습니다. 새 칸을 만들지 않습니다.

40일 마크는 기존 신호(2026-09-07~10-19)에도 대기 상태로 새로 생깁니다. 선정일로 대상을 잘라내지 않고 해당 신호·기간의 실제 마크 행을 조회합니다. 빈 칸은 다음 기준으로 표시합니다.

1. 실제 수익 결과가 있으면 그대로 표시합니다. 0%도 실제 결과입니다.
2. 마크 행 자체가 없음을 확인하면 ‘이 기간은 기록 시작 전’. 성과 DB 시작일 2026-09-07 이전 신호나 새 기록 활성화 전 등이 해당합니다.
3. 마크 행이 있고 아직 기간 전으로 가격이 쌓이는 중이면 ‘결과 기다리는 중 (남은 거래일 N일)’.
4. 기간이 지났고 필요한 가격이 없음을 확인하면 ‘가격을 못 구함’.
5. 행 존재·거래일·가격 누락의 근거가 없으면 ‘확인 필요’. 조회 실패를 행 없음으로 취급하지 않습니다.

N은 기존 거래일 달력·진입 및 평가 시작 기준으로 구합니다. 달력 일수나 단순 주말 제외로 계산하지 않습니다. 1·2·3개월은 20·40·60거래일, 1·5일은 접습니다. 종목 성적 집계 후 기간별 유효 결과 수를 ‘표본 N건’으로 작게 표시합니다.

집중 규칙의 20일 결과는 11월 중순, 40일 결과는 11/9 전후, 60일 결과는 12월 초로 모두 추정입니다. 화면 날짜 안내는 ui-copy.js의 first20FocusEstimate·first40Estimate·first60Estimate 한 곳에서만 바꿉니다. 예상일로 개별 마크의 상태를 추정하지 않습니다.

## A. 일컴 Chrome 360px 검사

헤르메스가 일컴 Chrome에서 구현 가지의 새 화면을 엽니다. 개발자 도구의 기기 도구모음을 Responsive로 설정하고 360×800, 페이지 확대 100%로 고정합니다. 기본 글자와 기본 글자의 130% 두 번 검사합니다.

큰 글자는 해당 화면의 문서에서 현재 html의 계산된 font-size를 확인한 뒤 그 값의 1.3배를 임시 적용합니다. 검사 전후 값을 기록하고 새로고침으로 원복합니다. 고정 px 문구가 그대로 남는지도 별도 기록해 큰 글자 검사가 실제 적용됐는지 확인합니다. iframe 미리보기라면 바깥 도구모음이 아니라 화면 문서를 대상으로 적용합니다.

저장 위치는 구현 가지의 `design-review/v9-final1020c/screens/360x800/default/`와 `design-review/v9-final1020c/screens/360x800/font130/`입니다. 표의 파일 이름을 각각 저장하고, 결과는 `design-review/v9-final1020c/mobile-check.md`에 화면별로 기록합니다.

통과 기준은 모두 충족해야 합니다.

- 페이지와 내부 표의 가로 스크롤 0. documentElement의 scrollWidth가 clientWidth를 넘지 않고, 표 안에서도 좌우 이동이 필요 없어야 합니다.
- 글자 잘림 0. 제목·빈 칸·출처·표본 수·버튼·팝업을 끝까지 읽을 수 있어야 합니다.
- 실제 누르는 영역의 너비와 높이가 각각 44px 이상. getBoundingClientRect 값으로 확인합니다.
- 한국어·일본어 줄바꿈 이상 0. 한국어 UI·번역 결과의 한자 금지와 일본어 원문 보존을 함께 확인합니다.
- 두 제목 상태, 번역 대기·검사 탈락, 세 날짜 구간과 세 빈 칸 이유를 확인합니다.

현재 없는 상태는 별도의 가상 검사 입력으로 재현하고 운영 자료와 섞지 않습니다. 일본어 기사·회사명·종목명 원문은 바꾸지 않습니다. 실제 브라우저 증거가 없으면 통과로 적지 않습니다.

## B. 같은 입력 비교

작업46과 47이 적용되고 40일 마크 생성까지 확인된 동일 운영 자료 한 벌을 읽기 전용으로 고정합니다. 기준 시각·원본 파일 목록·파일 해시·교정 후 자료 여부를 `design-review/v9-final1020c/inputs/manifest.json`에 기록합니다. 원자료에 비공개 내용이 있으면 공개 시안 저장소에 올리지 않고 내부 검사 폴더에만 둡니다.

같은 자료를 옛 화면과 새 화면에 각각 연결합니다. 실시간 재조회로 입력이 달라지지 않게 합니다. 비교표는 `design-review/v9-final1020c/same-input.csv`에 항목·옛 값·새 값·의도한 변경 번호·통과 여부를 적습니다.

필수 비교는 종목 수, 가격, 판정, ★ 테마 6개, 집중 테마 3개, 레인별 후보, 성과 숫자, 기사 수입니다. 종목·테마·기사 ID와 순서, 점수, 등락·판정 색도 함께 대조합니다. 값과 집합을 비교하며 화면 반올림으로 차이를 숨기지 않습니다.

허용하는 의도한 변경 목록은 다음뿐입니다.

1. 집중을 테마로 명시한 문구·중립 표식·출처 표시.
2. 날짜별 세 구간 분리와 시각 없는 10/20 선정분의 전환일 격리. 구간별 표시 수는 달라질 수 있으나 원본 기록은 보존.
3. 홈 성적표에서 확인된 집중 규칙의 ABC만 표시. D-only·미확인 전환일 제외. 종목 성적은 같은 종목·같은 진입일·같은 진입가일 때만 합치며 레인 배정 수는 신호 단위로 유지.
4. 20·40·60거래일을 기본 칸으로 표시, 1·5일 접기, 마크 행에 따른 빈 이유·남은 거래일·기간별 표본 수 표시. DB 수익률 자체는 동일.
5. 성과 메뉴 두 개와 안쪽 상세, 하루 변화의 알림홈 통합, 제목 버튼·모바일 줄바꿈 등 승인된 화면 구성.
6. 같은 날 진입가가 다른 기록은 별도 줄과 ‘같은 날 중복 N’ 표시. 진입 기준을 모르는 기록은 임의로 합치지 않음.
7. v9b에서 바꿨던 가상 일본어 제목은 원래 문장으로 복원. 실제 운영 기사 원문 변경은 허용 차이가 아님.

각 차이를 위 번호와 구체적인 대상 ID로 설명합니다. 목록에 없거나 설명되지 않은 차이는 모두 실패입니다. 원본 전체도 비교해 표시에서 빠진 기록이 데이터에서 삭제되지 않았는지 확인합니다. 같은 규칙·같은 입력의 화면 비교이지, 옛 선정 엔진과 새 선정 엔진을 비교하는 작업이 아닙니다.

## C. 옛 화면 보존과 되돌리기

헤르메스는 구현 전 옛 화면 HTML·JS·CSS·이미지의 전체 묶음을 별도 읽기 전용 폴더로 보존합니다. 원래 경로 구조와 파일 해시를 남기고, 새 화면은 다른 폴더에서 만듭니다. 공통 파일을 덮어써 옛 화면까지 바꾸지 않습니다. 현재 시안의 이전 기준 커밋은 `882762eddab8f4ac44e2639bee11b3be1a2476a3`이며 운영 롤백 버전을 뜻하지 않습니다.

운영의 실제 경로·배포 방식을 확인한 시그마가 인수 전에 ‘옛 화면 전체 묶음으로 전환하는 단일 명령’을 `design-review/v9-final1020c/rollback.md`에 적고 시험합니다. 서버 구성을 모르므로 명령이나 경로를 임의로 만들지 않습니다. 문서에는 이전 묶음·새 묶음·진입점·캐시 갱신 방법을 적습니다.

되돌리기는 2단계입니다. ① 준비된 단일 명령으로 화면 진입점을 옛 묶음으로 한 번에 전환하고 해당 화면 캐시를 갱신합니다. ② 홈·작전실·성과 화면을 열어 옛 버전과 기존 데이터 연결을 확인합니다. DB 복원이나 선정 엔진 변경은 없습니다. 읽기 사본에 연결한 검사 환경에서 옛 묶음으로 실제 한 번 되돌린 뒤 새 묶음으로 재진입하는 리허설을 수행하고 화면·버전·명령 결과를 저장합니다. 실제 단일 명령과 복구 리허설 결과가 준비되지 않으면 반영하지 않습니다.

## D. 반영 금지 조건

47의 main 반영 또는 10/21 17:30 배치 후 40일 마크 485건 이상 생성 확인이 끝나지 않으면 새 화면을 반영하지 않습니다.

범준 승인 없음, 이번 정정 문구 검토 미완료, 실제 브라우저 증거 없음, 같은 입력 비교 실패, 전환일 자료 임의 합산, 성과 숫자 출처 불명, 중복 진입 기준 임의 추정, 복구 리허설 미완료 중 하나라도 있으면 운영 반영하지 않습니다. 10/24는 후보일이며 10/25 확인 일정을 위해 검사를 생략하지 않습니다.

## E. 헤르메스 운영 자료 확인 체크리스트

운영 자료의 읽기 사본에서 확인하고 `design-review/v9-final1020c/operating-check.md`에 근거 파일·기준 시각·결과를 남깁니다.

- [ ] 47의 40일 마크·캐논·분할 교정 코드가 main에 들어간 커밋을 확인한다.
- [ ] 10/20 새 규칙이 처음 적용된 선정 시각을 확인한다. 선정 기록에 시각 열이 있는지, 시간대와 적용 기록이 일치하는지도 확인한다.
- [ ] 같은 날·같은 종목 중복 건수와 신호 식별정보를 확인한다. 레인 차이·회차 차이 구분 가능 여부, 진입일·진입가·진입 기준 일치 여부를 기록한다.
- [ ] 10/21 17:30 배치 후 40일 마크 485건 이상 생성됐는지 실제 행 수와 배치 결과로 확인한다. 기존 신호(2026-09-07~10-19)에 붙는지도 확인한다.
- [ ] 교정 후 성과 숫자가 화면과 일치하는지 확인한다. 전달받은 참고값은 1일 평균 −0.084%, 5일 평균 −1.050% 부근이다. 값이 다르면 표본·기준 시각·교정 적용을 확인하며 화면 숫자를 참고값에 맞춰 고정하지 않는다.
- [ ] 360×800·글자 130% 실제 검사와 같은 입력 비교를 완료한다.
- [ ] 읽기 사본에 연결한 검사 환경에서 옛 화면 묶음으로 실제 한 번 되돌리고 기존 데이터 연결을 확인한 뒤 새 묶음으로 재진입한다. 명령 결과와 화면을 남긴다.

현재 아스트라가 확인한 것은 가상 입력·코드 실행·비시각 화면 검사입니다. 위 운영 체크리스트, 실제 배포 경로·명령과 최종 승인은 확인하지 못했습니다. 선정 엔진·서버 쓰기·DB 칸·번역 엔진은 변경하지 않았습니다.
