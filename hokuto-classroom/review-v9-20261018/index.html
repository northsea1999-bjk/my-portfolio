1. 지금 검토하는 것은 무엇인가

새 첫 페이지는 알림 홈, 기존 호쿠토는 자세한 확인과 판단을 하는 화면입니다.

첫 사용자는 일본어 자료를 직접 읽기 어려운 한국인 일본 주식 투자자입니다. ‘내 종목에서 무엇이 달라졌고, 왜 중요한지, 다음에 무엇을 확인할지’를 빠르게 이해하는 것이 목표입니다.

  • 현재 요청: 디자인·정보 구조·연결성 검토. 이번 검토 자체가 구현·배포·서버 변경 지시는 아닙니다.
  • 검토할 자료: 이 안내, v9 고정 시안, 정적 화면 사본, 고정 버전 소스. 현재 공개 시안은 나중에 바뀔 수 있으므로 버전 대조는 고정 시안을 우선합니다.
  • 판단 경계: 모든 회사·가격·기사·분석·성적은 가상입니다. 운영 데이터 연동, 실제 기록 보존, 수익 개선, 실제 시세 수신을 구현했다는 뜻이 아닙니다.
  • 유지할 결정: 현재 색감과 종목 중심 홈, 리서치부터 신규매수까지의 여섯 단계, 기존 기능의 접근성, 분석과 당시 자료·기록·성적표의 연결.
  • 별도 과제: 뉴스 모델 성능, 라야 학습, 서버 운영, 텔레그램, 결제와 회원 시스템은 이번 UI 검토 범위가 아닙니다.

새 창에서 기존 호쿠토를 여는 연결은 사용자 브라우저에 저장된 주소를 씁니다. 이 공개 자료에는 개인 서버 주소·실제 보유 자료·로그인 정보가 없습니다.

2. 무엇을 바꿨는가

첫 화면의 목적

‘내 일본 주식의 중요한 변화’라는 제목과 보유 경고 한 건을 먼저 보여줍니다. 변화, 숫자 근거, 다음 확인, 이동 버튼을 붙였습니다. 새 매수대상과 후속 뉴스는 짧게 배치했습니다.

회사를 따라가는 연결

테마 선택 → 후보 회사 → 실적 확인 → 같은 회사의 판정으로 이어집니다. 보유종목은 내 주식, 신규 매수대상은 신규매수실로 나뉩니다.

반복을 줄인 곳

화면마다 반복되던 홈·전체 메뉴 버튼, 회사 카드 아래의 중복 다음 단계, 자동 연관 메뉴 카드, 반복 안내를 줄였습니다. 결정실의 숫자와 판정 필터를 합쳤습니다.

분석에 집중하는 화면

뉴스·방에서 종목 분석을 열면 알림 홈을 다시 끼워 넣지 않습니다. 해당 회사의 현재 분석·당시 입력·변화 기록·성적표를 보고 출발 화면으로 돌아갑니다.

3. 기존 호쿠토와의 대응

순서화면확인하는 것기존 운영 위치
1리서치 회의실전체 테마의 순위·강도·돈몰림 요약사무실 room1 → ▶ 브리핑
2리서치 작전실주도·관찰·전환 테마hokuto_today.html
3펀드매니저 전략실선정 조건을 충족한 회사와 이유사무실 room2 → ▶ 브리핑
4펀드매니저 종목검증실EPS·실적·자료 상태recommend.html
5결정실매수대상·보류·제외와 근거decision_room.html

  • 여섯 단계는 읽는 순서입니다. 여섯 개의 새 통과 조건을 만들지 않았습니다. 알림은 이미 나온 결과로 바로 이동할 수 있습니다.
  • 종목검증실은 EPS로 새 탈락을 만들지 않습니다. 최종 판정은 결정실의 역할입니다.
  • A/B/C 종목과 운영 D 대표가 결정실로 이어집니다. 운영 D는 독립 범위이며 모든 회사를 TOP6 통과자로 제한하지 않습니다. 여기의 A/B/C/D는 후보 선정 레인으로, 뉴스 중요도 A/B/C와 다른 분류입니다.
  • 보유종목은 결정실 목록과 관계없이 점검합니다. 보류·미입력 종목을 다른 회사의 신규매수 카드로 바꿔 보여주지 않습니다.
  • 신규매수의 가격은 운영 소스 기준 지연 관측입니다. 차트 기준일·가격 시각·수신 시각을 분리하며, 가격 수신만으로 진입 신호를 만들지 않습니다.
  • 실제 사무실 링크는 해당 위치까지만 엽니다. 브리핑 자동 실행 경로는 없어서 실제 사무실에서는 ▶ 브리핑을 눌러야 합니다.

보조 기능도 보존했습니다

보유·뉴스: 내 주식, 뉴스룸, 테마뉴스 / 변화·성과: 사장실·놀이공원, 성과기록, 선정성적 / 참고: 북두테마 상세, BNF 신호실, 트레이딩 상황실.

기존 독립 기능 13개 + 사무실 브리핑 2개 = 운영 진입점 15개입니다. 기존 오늘·사무실 입구 2개, 새 홈 기록 시안 2개까지 총 19개 경로이며 운영 화면 생성 수를 뜻하지 않습니다.

4. 웹클로드에게 요청하는 검토

  1. 첫인상: 처음 보는 사람이 이 서비스가 무엇인지, 무엇부터 봐야 하는지 쉽게 알 수 있는가? ‘5초 이해’는 목표이며 실측 합격으로 표현하지 말아 주세요.
  2. 누락·중복: 기존 기능이 빠지거나 같은 역할을 여러 화면이 반복하는가? 제거·이동으로 간결해지는 곳을 우선해 주세요.
  3. 연결: 같은 테마·회사가 다음 화면과 돌아온 화면에서 유지되는가? 보유·보류·자료부족 분기가 맞는가?
  4. 오해 가능성: 후보 선정, 실적 확인, 최종 판정, 진입 조건, 실제 수익을 혼동하게 하는 표현이 있는가? 가상 자료와 실제 운영을 혼동시키는 곳이 있는가?
  5. 기록: 현재 분석 → 당시 입력 → 과거 변화 → 같은 회차의 성적표가 이해되는가? 시안만 있는 저장·분석 기능을 운영 완료로 오해하지 않는가?
  6. 좁은 화면: 브라우저로 확인할 수 있으면 휴대폰 폭에서 주요 정보·메뉴·다음 행동이 잘 보이는지 확인해 주세요. 웹 읽기만 가능하면 배치·클릭은 미확인으로 남겨 주세요.

이미 코드 검사로 확인한 항목을 근거 없이 다시 방어하자고 제안하지 마세요. 다만 실제 반례가 있으면 재현 경로와 함께 지적해 주세요.

수정은 사용자 영향·발생 가능성·기존 방어·작업 비용을 비교해 필수 / 선택 / 불필요로 나눠 주세요. 이번 요청은 검토이며 헤르메스 작업 지침이나 운영 변경 지시를 작성할 단계가 아닙니다.
