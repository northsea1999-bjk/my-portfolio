# 알림 홈과 기존 호쿠토의 연결 — v9

2026-10-18. 공개 디자인 미리보기를 수정했다. 운영 서버·판정 계산·뉴스 처리·보유 자료는 변경하지 않았다. 표시된 회사·가격·기사·분류는 가상 예시다. 승인된 알림 홈의 CSS는 유지했다.

## 이번 단순화 — v9

- 첫 화면 제목을 ‘내 일본 주식의 중요한 변화’로 바꿔 용도를 바로 알 수 있게 했다. 별도의 홍보 배너나 메뉴를 추가하지 않았다.
- 같은 크기의 알림 3개를 ‘먼저 확인할 보유 경고 1개 + 새 매수대상·후속 뉴스 2개’로 정리했다. 변화, 숫자 근거, 다음 확인, 도착 화면이 한 묶음이다. 가상 예시의 첫 상세도 같은 보유종목을 선택한다.
- 보유 경고를 열면 해당 종목의 직전 기록 대비 변화를 차트보다 먼저 보여준다.
- 회사 분석을 열면 알림 홈·전체 종목을 다시 끼워 넣지 않고 그 회사의 분석·입력 자료·기록에 집중한다. 출발 화면으로 돌아갈 때 테마·종목·필터·날짜·스크롤은 유지한다.
- 공통 이동 줄에서 반복되던 홈·전체 메뉴 버튼을 뺐다. 데스크톱 주 메뉴와 휴대폰 하단 메뉴는 유지하고, 이동 줄에는 이전 화면만 둔다.
- 회사·테마 카드가 다음 이동을 제공하는 곳에서는 화면 아래의 중복 ‘다음 단계’를 뺐다. 회의실의 요약 → 작전실만 화면 단위 이동을 유지한다. 여섯 단계 탐색과 모든 운영 메뉴는 보존한다.
- 결정실의 판정별 숫자 카드와 필터를 하나로 합쳤다. 전체·매수대상·보류·제외 4개로 같은 기능을 한다.
- 매 화면 하단에 자동으로 붙던 연관 메뉴 카드, 홈 하단·옆면의 반복 설명, 화면마다 반복되던 시안 안내 상자를 줄였다. 상단의 가상 자료 표시와 기존 화면 연결은 유지한다.
- 색상·전체 종목 목록·성적표·분석과 당시 입력 자료는 유지한다. ‘5초 안에 이해’는 설계 목표이며 사용자 실측 결과가 아니다.

## 구조와 근거 — v8에서 유지

기존 사무실 안의 리서치 회의실과 펀드매니저 전략실 브리핑을 별도 진입점으로 복원했다. v7은 독립 HTML 메뉴만 기준으로 삼아 이 두 단계를 빠뜨렸다. 이제 전체 메뉴의 맨 위에 사용자가 읽는 여섯 단계를 두고, 같은 테마·회사를 따라갈 수 있게 했다. 보조 메뉴에는 이 여섯 항목을 반복하지 않는다.

## 여섯 단계 대응표

| 순서 | 화면 | 역할 | 실제 운영 위치 |
|---|---|---|---|
| 1 | 리서치 회의실 | 테마 전체의 순위·강도·돈몰림 요약 | 사무실 `hokuto_main.html#room1` → 리서치센터의 ▶ 브리핑 |
| 2 | 리서치 작전실 | 주도·관찰·전환 테마 확인 | `hokuto_today.html` |
| 3 | 펀드매니저 전략실 | 선정 조건을 충족한 후보와 이유 | 사무실 `hokuto_main.html#room2` → 펀드매니저실의 ▶ 브리핑 |
| 4 | 펀드매니저 종목검증실 | 후보 회사별 EPS·실적·자료 확인 | `recommend.html` |
| 5 | 결정실 | 매수대상·보류·제외 최종 판정과 근거 | `decision_room.html` |
| 6 | 신규매수실 | 차트 기준과 다음 거래일 시가·장중 관측 | `newbuy_room.html` |

번호는 읽는 순서다. 여섯 개의 독립적인 통과 조건을 새로 만든 것이 아니다. 종목검증실은 EPS 상태로 후보를 탈락시키지 않는다. A/B/C 종목과 운영 D 대표가 결정실에 들어가며, 운영 D는 독립적으로 확장된 테마 범위를 사용한다. 모든 후보를 TOP6 테마 통과자로 제한하지 않는다.

회의실·전략실의 운영 링크는 사무실의 해당 위치를 연다. 기존 소스에 URL로 브리핑 팝업을 자동 실행하는 기능은 없어, 실제 화면에서는 ▶ 브리핑을 눌러야 한다. 미리보기 내부에서는 각 내용을 직접 열어 볼 수 있다.

## 같은 대상을 이어 보는 방법

- 회의실에서 테마 선택 → 작전실에서 상태 확인 → 해당 테마의 전략실 후보 → 회사 실적 검증 → 같은 회사의 결정실 판정.
- 전략실의 레인 필터와 회사 선택을 구분한다. 후보 조건은 A/B/C/D, 회사 실적 상태는 개선·변화미미·자료부족 등으로 따로 표시한다.
- 결정실의 보유종목은 ‘내 주식’으로 연결한다. 신규매수는 매수대상이고 신규매수 카드가 있는 회사에만 연결한다.
- 보류·미입력 종목을 다른 회사의 신규매수 카드로 바꿔 보여주지 않는다. 대상이 없으면 그 이유를 표시한다.
- 회사 상세의 분석·당시 입력 자료·지난 기록은 계속 열 수 있다. 돌아오면 테마·종목·날짜·필터·읽던 위치를 보존한다.
- 가상 예시: AI 소프트웨어 → 세이운 소프트(DEMO-E) → EPS 개선 → 매수대상 → 신규매수실. 가격 수신만으로 진입 신호를 생성하지 않는다.
- DEMO-D는 보유 관리, DEMO-F는 보류, DEMO-G는 선정 자료 미확인 예시다.

## 가격 시각

운영 코드의 가격은 Yahoo 지연 관측이다. ‘실시간’으로 표시하지 않는다. 전 거래일 차트 기준, 다음 거래일 시가, 완료된 1분봉 종가, 가격 기준 시각, 수신 시각을 구분한다. 미리보기는 개장 전과 장중 수신 예시를 전환할 수 있다. 가상 가격과 시각을 운영 관측으로 해석하면 안 된다. 기존 차트 신호와 매수대상 판정은 가격 수신 여부와 별개다.

## 보존한 보조 메뉴

| 묶음 | 기능과 실제 경로 |
|---|---|
| 보유와 뉴스 | 내 주식 `holdings_room.html`, 뉴스룸 `news_board.html`, 테마뉴스 `theme_news.html` |
| 변화와 성과 | 사장실·놀이공원 `hokuto_fun.html`, 성과기록 `performance_room.html`, 선정성적 `selection_results.html` |
| 테마·전략 자료 | 북두테마 상세 `research_new.html`, BNF 신호실 `bnf_signal.html`, 트레이딩 상황실 `trading_logic.html` |

기존 독립 기능 13개에 사무실 브리핑 진입점 2개를 더해 15개 항목이다. 운영 HTML 생성 수가 15개라는 뜻은 아니다. 오늘 화면과 옛 사무실 입구도 보존한다. 종목별 변화·기록과 성적표는 새 홈의 별도 시안이다. 운영에 기록 저장 기능을 추가한 것은 아니다.

## 주소와 복귀

실제 호쿠토 주소는 사용자가 입력하면 브라우저에만 저장한다. 한국어 `/ko/` 경로는 유지하되, 사무실 브리핑은 루트의 `hokuto_main.html#room1/room2`로 연결한다. 실제 운영 화면은 새 탭에서 열린다. 공개 코드에는 개인 서버 주소·실제 보유 자료가 없으며 DEMO 코드를 실제 운영 URL에 넘기지 않는다.

기존 별칭 `manager`는 전략실, `trading`은 신규매수실, `space`는 사무실, `themeLab`은 북두테마 상세로 연결한다. 브라우저 뒤로·앞으로와 공통 이전 화면을 지원한다.

## 검증

`node hokuto-classroom/tests/navigation-connections.test.cjs`: 15개 운영 항목의 중복·누락, 19개 전체 경로, 6단계 테마·회사 이동, 종목검증과 최종 판정 분리, 가격 시각 구분, 보류·보유·미입력 분기, 원래 화면·필터·날짜·스크롤 복귀, 운영 주소·사무실 브리핑 경로를 검사한다.

새 첫 요약의 알림 도착점, 회사 분석에서 홈이 다시 나타나지 않는 동작, 출발 화면 복귀, 판정 필터 통합도 검사했다. 브라우저 없는 상태 검사다. 지원되는 브라우저 검수 기능이 없어 실제 화면 렌더링·휴대폰 캡처 검수는 수행하지 못했다. 기존 홈 스타일 파일은 유지하고 마지막에 읽는 탐색 스타일에 새 브리핑·상세 화면 규칙을 추가했다. 운영 서버 접속·운영 반영은 하지 않았다.
